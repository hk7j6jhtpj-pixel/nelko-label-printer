## 実機ログ

### 2026-10-17 Windows 11 / BLE
- `p21 scan` で名前 `P21`、ランダム形式の BLE アドレス（RSSI -58）として BLE で見えた。Classic のペア済み機器には無し。
- アドバタイズにサービス UUID `ff00` は含まれていなかった（名前で検出）。
- ペアリングなしで GATT 接続でき、`ESC ! o` / `BATTERY?` / `CONFIG?` が Classic と同じ形式で返ってきた:
  - 状態: Ready、14×40 mm / ギャップ紙 / 白（RFID 読み取り OK）
  - 電池 99%（充電中）
  - CONFIG: ハードウェア **0.0.1** / ファームウェア **0.0.1**、203 dpi、自動オフなし、ビープ オン
    （既存資料の 0.0.3 / 4.2.4 とは違う系列。BLE 専用ロットの可能性）
- USB（COM25）は何を送っても `ERROR0`（[03-connection-by-os.md](03-connection-by-os.md)）。
- 初回印刷（14×40、テスト用ラベル: 枠 + 左上の黒い四角 + テキスト + QR）を BLE で送信:
  - 3515 バイトを 200 バイト / 15ms 刻みで送信、所要約 8 秒（接続込み）。
  - 応答 `000c011203000301121215280f0eed03`（Classic 機の実機ログと完全一致）、その後 readiness が Ready に戻った。
  - 実物の仕上がり: **向き OK（時計回り回転で正しい）、外枠 4 辺とも欠けなし、QR 読み取り OK、濃さ（DENSITY 15）OK**。

### 2026-10-18 AI エージェントによる実機印刷（BLE）
- `AGENTS.md` だけを読んだサブエージェントが、`p21 info` で準備状態を確認 → ラベル JSON を設計 → `p21 render --debug` で確認 → `p21 print -c 1` を 1 回だけ実行。
- 結果: exit 0、acknowledged / finished とも true、応答 `000c011203000301121215280f0eed03`、所要約 9.3 秒（BLE 接続込み）。
- 実物の仕上がり: プレビューどおり（向き・枠・QR・日時とも正常、ユーザーが写真で確認）。
- それまでに 4 体のエージェント（CLI / MCP / GUI / 敵対的テスト）が mock で検証し、見つかった不具合を修正済み（tests/test_regressions.py）。
