# 02. 通信プロトコル

複数の OSS 実装（[04-prior-art.md](04-prior-art.md)）のソースと、実機ログ（KalebCole の記録）から再構成した仕様。

## 全体

- トランスポートはバイトストリーム（Classic SPP / BLE GATT どちらも同じバイト列）。
- **コマンドは ASCII + CRLF (`\r\n`) 終端**。応答も基本 CRLF 終端（例外: 状態応答は 16 バイト固定の CRC 付きバイナリ）。
- シリアルとして開く場合は 115200 bps, 8N1（仮想 COM なので実質意味はない）。
- 1 回の接続で「準備状態の確認 → ジョブ送信 → 応答待ち」を行う。

## コマンド一覧

| コマンド | 応答 | 説明 |
|---|---|---|
| `ESC ! ?` (`1B 21 3F`) + CRLF | 1 バイト | 準備状態。`00`=Ready, `01`=カバー開, `04`=紙なし, `20`=印刷中 (Busy) |
| `ESC ! o` (`1B 21 6F`) + CRLF | 16 バイト（CRC 付き） | 詳細状態。TSPL2 では「一時停止解除」。公式アプリは繰り返し送っている |
| `BATTERY?` | `BATTERY ` + 2 バイト + CRLF | 1 バイト目: 残量（**BCD**, 例 `0x75`=75%）、2 バイト目: 充電中フラグ。充電中は常に 99% |
| `CONFIG?` | `CONFIG ` + 10 バイト + CRLF | 設定・バージョン（後述） |
| `BEEP <b>` | — | `<b>` は生バイト `0x00`(off) / `0x01`(on)。ASCII の "0"/"1" ではない |
| `TIMEOUT <b>` | — | 自動電源オフ。生バイト `0`=しない, `1`=15分, `2`=30分, `3`=60分 |
| `SELFTEST` | — | セルフテスト印刷 |
| `INITIALPRINTER` | — | **工場出荷時リセット**（使わないこと） |
| `BAR` | — | 全面黒を印刷（使い道なし） |
| `BARCODE` / `QRCODE` | — | 動かない / 壊れた出力。**バーコードや QR は PC 側で画像化する必要がある** |

### 印刷ジョブ

```
ESC ! o CRLF
SIZE 14.0 mm,40.0 mm CRLF
GAP 5.0 mm,0 mm CRLF
DIRECTION 1,1 CRLF
DENSITY 15 CRLF
CLS CRLF
BITMAP 0,0,12,284,1,<3408 バイトの生ビットマップ> CRLF
PRINT 1 CRLF
```

- 14×40 で `PRINT 1` のとき、ジョブ全体はちょうど **3515 バイト**（実機ログと一致）。
- `SIZE` はラベルの物理サイズ（mm, 小数1桁）。
- `GAP 5.0 mm,0 mm` は全実装が固定で送っている（RFID で自動認識されるので実質無視されている可能性）。
- `DIRECTION` は P21 では効果がないとの報告。`1,1` と `0,0` の両方が使われている。
- `DENSITY` は濃度 0〜15（実装により 1〜15 にクランプ）。既定 15。
- `BITMAP x,y,幅バイト数,高さドット,モード,データ`
  - 幅バイト数 = 96/8 = 12、高さ = 284。
  - モードは `1`（多くの実装）または `0`（CzJLee）。TSPL2 では 0=上書き, 1=OR, 2=XOR。CLS 直後なのでどちらでも同じ結果。
- `PRINT n` で n 枚コピー。
- ジョブ送信後、プリンタは **16 バイトの状態応答**（`ESC ! o` と同じ形式）を返す。

## ビットマップ形式

- 縦長 **96 (幅) × 284 (高さ)**、行優先 (row-major)、1 行 12 バイト。
- **MSB が左端のピクセル**。
- **ビット 0 = 黒（印字する）、ビット 1 = 白（印字しない）**。
  - Pillow の `mode "1"` の `tobytes()` がそのまま使える（Pillow も 0=黒, 1=白）。
  - データが足りないと残りが黒くなるので、必ず 3408 バイトぴったり送る（足りなければ `0xFF` で埋める）。
- **向き**: 横長 284×96 のキャンバスでデザインし、**時計回りに 90° 回転**して 96×284 にする。
  - KalebCole の実機キャリブレーション（「黒マーク=左上」）で pixel-perfect と確認。
  - Fyne-P21-Print / julienvincent / CzJLee も時計回り（Pillow の `rotate(-90, expand=True)` = `Image.Transpose.ROTATE_270`）。
  - 回転後の 1 行目 = 横長キャンバスの左端の列。

## 状態応答（16 バイト）

例: `20 0c 01 12 03 00 03 01 12 12 15 28 0f 0e 0d 22`

| オフセット | 意味 | 例 |
|---|---|---|
| 0 | 準備状態（`ESC ! ?` と同じコード） | `0x20` = Busy / `0x00` = Ready |
| 1 | データ長？ | `0x0c` = 12 |
| 2, 3 | 不明 | |
| 4 | ラベル色: 0=不明, 2=透明, 3=白, 4=ピンク, 5=青, 6=黄 | `0x03` = 白 |
| 5 | 不明 | |
| 6 | 角丸 or 余白？ | |
| 7 | 紙種: 0=連続紙, 1=ギャップ紙, 2=黒マーク | `0x01` |
| 8〜10 | 不明 | |
| 11 | ラベル長 (mm) | `0x28` = 40 |
| 12 | 最大ラベル幅 (mm)？ | `0x0f` = 15 |
| 13 | ラベル幅 (mm) | `0x0e` = 14 |
| 14〜15 | **CRC16**（下記） | |

- 幅・長さが両方 0 なら RFID タグを読めていない（非純正ロールなど）。
- 実機ログで印刷直後の応答は `00 0c 01 12 03 00 03 01 12 12 15 28 0f 0e ed 03`（先頭 `00` = Ready）。
  ただしこれが「印刷成功」を意味するかは確定していない（KalebCole も「受理の形」としか扱っていない）。

### CRC16

CRC-16/MODBUS（初期値 `0xFFFF`、反転多項式 `0xA001`、LSB first）を先頭 14 バイトに対して計算し、**ビッグエンディアン**で末尾 2 バイトに置く。

```python
def crc16(data):
    crc = 0xFFFF
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = (crc >> 1) ^ 0xA001 if crc & 1 else crc >> 1
    return crc.to_bytes(2, "big")
```

テストベクタ: `200c011203000301121215280f0e` → `0d 22`

## CONFIG? 応答

例: `CONFIG ` + `00 cb 00 00 03 04 02 04 02 01` + CRLF

| オフセット | 意味 | 例 |
|---|---|---|
| 0 | プロトコル種別（0 = TSPL？） | `00` |
| 1 | DPI | `cb` = 203 |
| 2〜4 | ハードウェアバージョン | `0.0.3` |
| 5〜7 | ファームウェアバージョン | `4.2.4` |
| 8 | 自動電源オフ設定（TIMEOUT と同じコード） | `02` = 30分 |
| 9 | ビープ（0/1） | `01` = on |

## タイミング・送り方の注意

- **Classic RFCOMM**: MTU（macOS 実測 666 バイト）以下に分けて書くのが安全。Windows/Linux のソケットや仮想 COM は OS 側で分割してくれる。
- **BLE**: `min(MTU-3, 200)` バイトずつ **Write Without Response**、チャンク間 **15 ms** 待つ（受信バッファが小さいため）。
- 応答待ちのタイムアウトは 1〜3 秒程度で全実装が動いている。
- **ジョブを送り始めたら自動リトライしない**（二重印刷の危険。KalebCole の安全原則）。
- macOS では RFCOMM を閉じた直後の再オープンが失敗することがある（ACL 切断待ちが必要）。
- 印刷前に `ESC ! ?` で `00` を確認してから送ると安全。
